# GTO 5.1 — формулы старшинства внутри категории

**Актуально:** 2026-11-04 · **код:** bots/hand_seniority_51.py + bots/gto_postflop_50.py.

**Первоисточник:** [SKACHKOV POKER → Старшинство](https://docs.google.com/spreadsheets/d/1UE7P0qatiIn8nae8sGwTIxMM7Vx2vFYeGR4BMDOnhJk/edit#gid=1921062352), строки 3–11. Контрольные 990 физических пар из строк 13–22 **не входят в игровой метод**.

## 1. Принцип

Вероятность категории P_c берём из формул P0–P3, S/F, y и H. Сами эти формулы GTO 5.1 **не меняет**.

Находим внутри категории c число опасных D и безопасных B рангов (для стрита — высот/путей), число равных T. Считаем долю выигрыша Hero:

\[
\boxed{r_c=(B+0.5T)/(D+B+T)}
\]

\[
\boxed{q_{\rm Hero}=\sum_{i<c}P_i+P_c r_c}
\]

Для двух карт оппонента, каждая из которых может дать старший кикер, используем приближение двух попыток:

\[
r_c \approx ((B+0.5T)/(D+B+T))^2.
\]

При пустом наборе допустимых вариантов r_c = 0.5. Ничья весит половину банка **для HU-прокси**. Истинный multiway share потребует отдельной модели.

В GTO 5.0/5.0.5 вместо реального r_c всегда стоит 0.5. В 5.1/5.1.5 мы заменяем эту константу. Не прибавляем вероятность более высоких категорий к q: она автоматически находится выше Hero в ранговой шкале.

## 2. Правила девяти категорий

| Категория | Счёт рангов/вариантов, которые бьют Hero | Особенности |
|---|---|---|
| Старшая карта | Из 13 рангов берём свободные, не образующие пару с бордом; сравниваем главный свободный кикер, при равенстве — второй | P(сильнее | та же категория), не любое попадание в борд |
| Пара · непарный борд | Доля опасных пар из рангов борда, отдельно опасных карманных пар из 13 рангов | Вес PP = min(1, x/P_pair); **не прибавлять x ещё раз** |
| Пара · парный борд | Общая пара одинаковая; смотрим кикер и 2 шанса найти старший кикер | PP в эту категорию повторно не добавляем: PP чаще создаёт две пары |
| Две пары | Старшая → младшая → кикер; при P0 выбираем пары рангов из 3–5 рангов борда (не больше 10 маршрутов), при P1 — общий старший ранг + второй ранг; при P2 — кикер | В пределах одной категории |
| Тройка | Сравниваем ранг сета/трипса; на общей тройке сравниваем кикеры двумя шансами | Шанс не встретить опасный кикер ≈ (B/N)^2 |
| Стрит | Среди 10 высот от 5 до A (включая wheel A2345) считаем возможные маршруты с не более чем двумя недостающими доступными рангами; выше Hero = опасно | Никакого перебора 990 физических рук |
| Флеш | Считаем одномастные свободные ранги, дающие пятёрку выше/ниже пятёрки флеша Hero | При F3 второй нужный одномастный ранг выбираем приближённо; процент самой категории уже учитывает возможность флеша |
| Фулл-хаус | Тройка → пара; на общем полном фулл-хаусе опасны только старшие карманные пары, их вес x × D_PP/N_PP | Для общего FH r ≈ 1 − min(1, x×D_PP/N_PP / P_FH). Ранее известная P категории не должна умножаться на D_PP/N_PP второй раз |
| Каре | Ранг каре → кикер; при каре на борде 2 шанса найти старший кикер | Если Hero владеет четвёртой картой ранга, соперник не может повторить то же каре |
| Стрит-флеш | До 10 одномастных высот (wheel + 6…A); сравниваем высоты допустимых путей с не более чем 2 недостающими одномастными картами | Не приравнивать частоту SF к обычному стриту |

В каждой составляющей считаем не более **13 рангов**, для прямого стрита не более **10 высот**, для двух пар на P0 не более **10 пар рангов борда**. Для доступности ранга проверяем физические блокеры Hero/борда. Но **не перебираем допустимые двухкарточные руки противника** и не запускаем Monte Carlo для игры.

## 3. Две версии и два контроля

| Стратегия | Старшинство r_c | Округление P_c |
|---|---|---|
| GTO 5.0 | 0.5 | нет |
| GTO 5.0.5 | 0.5 | шаг 5 п.п. |
| **GTO 5.1** | по рангам/кикерам/маршрутам | **нет** |
| **GTO 5.1.5** | **то же** | **шаг 5 п.п.** |

Округляются **только** проценты категорий P_c: 43.7% → 45%, 12.1% → 10%. Сначала округлить каждую категорию, потом нормализовать в EV, не принуждая исходную таблицу к сумме 100%. r_c отдельно **не округляется**.

## 4. Проверочные примеры

- Q♥ 8♠ 3♦ 2♣ 7♥: A♦Q♠ — топ-пара с кикером A; 4♣4♦ — слабая карманная пара. В 5.1 оценки r_pair **различаются** (AQ выше 44); в 5.0 обе руки имеют 0.5.
- 9♠ 8♠ 3♠ 2♠ 5♦, Hero T♠4♣: флеш до T; опасные A♠ K♠ Q♠ J♠, безопасные 7♠ 6♠ 5♠ 4♠. D=4, B=4: r ≈ 0.5; P(сильнее внутри флеша) ≈ P_flush×0.5 (в простом Any Two).
- A♣ 2♦ 3♥ T♠ Q♣, Hero 4♣5♦: стрит до 5; опасный путь J+K до туза. Считаем высоты путей, а не физические пары.
- K♣ K♦ K♥ 8♠ 8♣: фулл-хаус на борде. Угроза старших карманных пар взвешивается **x**, не всей массой P_fullhouse.

## 5. Точные границы применимости

- Это **аппроксимация старшинства**, а не истинное условное equity или GTO/Nash. Особенно приблизительны двухкарточные пути к двум парам, фулл-хаусу, флешу и кикерам: веса рангов и мастей по диапазонам ещё не выучены.
- P0–P3 категории и K,x сейчас используют **Any Two**: x=5.88%, K=1. Нет адаптации x/K к каждому оппоненту. Действия оппонента фильтруют только EV-квантили по уже существующей модели.
- На F/T оцениваем **текущую** комбинацию; прежняя draw-поправка остаётся отдельным эвристическим слагаемым. Не путать с точным будущим showdown.
- На бордах P4/PH GTO 5.1 пока наследует **консервативный fallback GTO 5.0**, поскольку формулы распределения для этих типов не откалиброваны. Наличие правила старшинства каре/фулл-хауса НЕ означает, что для P4/PH уже активирован расчёт EV.
- В мультипотах действует прежнее приблизительное произведение условных эквити. Ничьи не моделируются точно.
- Shadow EV regret — **по выбранной эталонной стратегии**, не фактический проигрыш, не solver truth.
- Не изменять 5.0/5.0.5 при последующей калибровке GTO 5.1. Для проверки — одинаковые seed, составы турниров, парные Shadow состояния, разбивка F/T/R, HU/Multiway и P/S/F.


## 6. Контроль вычислений по одной раздаче (2026-11-04)

Новый журнал симулятора хранит до 100 постфлоп-раздач *каждого бота из последнего турнира*; на экране доступны последние 5 / 10 / 20 / 50 / 100. Старые сохранённые серии содержат только 5 и не могут восстановить более ранние решения.

Кнопка «Показать точный расчёт Any Two» запускает **отдельный read-only аудит** выбранного шага, а не изменение игровой формулы:

- Флоп: 1081 возможная двухкарточная рука OPP: C(47,2).
- Тёрн: 1035 допустимых рук: C(46,2).
- Ривер: 990 допустимых рук: C(45,2).

Для каждой проверяем лучшие пять карт по eval_hand(OPP, board) и сравниваем с eval_hand(Hero, board). Карты HERO и борда блокируют недоступные руки OPP. Выводятся: точная частота категории Hero у OPP, точная доля слабых/равных/старших рук OPP внутри той же категории, отдельная доля побед Hero внутри категории с 1/2 за ничью, и общая точная HU-доля против Any Two.

**Критическое различие:** на флопе/тёрне это точное старшинство *текущих готовых рук*, НЕ вероятность победы после выхода будущих карт. На ривере общая доля уже соответствует showdown HU против *равномерного Any Two*; нельзя называть её точным multiway EV, GTO-оптимумом или распределением OPP после его Call/Bet. Проверка проводится исключительно по запросу, поэтому быстрый игровой алгоритм GTO 5.1 не использует 990 перебираемых рук.

Показатель «Any Two P(повтор ранга)» в исходном логе рассчитывался только из рангов публичного борда, по формуле структурного повторения. Значения 38,78% / 48,94% на разных непарных флопах/тёрнах и 100% при парном борде не означают вероятность попадания OPP в старшую пару или вероятность победы. Для этой задачи служит отдельный точный аудит текущих рук.
