# SKACHKOV Poker System — Railway (Stage 1)

This branch deploys the **existing** Texas Hold'em simulator with a protected
browser control panel. The tournament engine and A17 TAG V3 are not changed.
It is based on `feat/replit-simulator-20261014`, which contains the web runner.

## Deploy from GitHub

1. Open https://railway.com/new and select **Deploy from GitHub repo**.
   Grant access to `Laosez/Texas-Holdem-AI` if requested.
2. Pick **branch** `feat/railway-simulator-20261014` under the Railway
   service's Source settings (not `main`). Deploy from the repository root.
3. **Before or during first deployment**, add Variables:
   - `POKER_RUNNER_KEY`: a long, private random secret you choose.
   - `POKER_DATA_DIR`: `/data` (recommended only with a volume; otherwise
     omit and the app uses ephemeral `output/replit_runs`).
4. For persistent experiment results, attach a Railway Volume mounted at
   **`/data`** to the simulator service. Use a single service replica.
5. Build: `Dockerfile` (Python 3.11 slim, no heavy training dependencies).
   Start command: `python -u replit_simulator.py` (in railway.json).
   Server listens on `0.0.0.0:$PORT`. Readiness: GET `/health` (HTTP 200
   only when `POKER_RUNNER_KEY` is configured).
6. In service **Settings → Networking → Generate Domain**, generate
   an HTTPS `*.up.railway.app` URL; open it and enter the key.
7. Click **Восстановить контроль V3**, set **2 tournaments**, launch smoke,
   then run the historical **90-tournament** control experiment.
8. Download results as ZIP and keep a separate copy. Reports generated by
   the exporter include CSV range matrices and JSON tournament reports.

## Experiment settings

- Nine bot profiles: `split:gto:smart`, `split:gto:gto`,
  `split:gto:tag_punisher`, `split:gto:maniac_mixed`,
  `split:gto:baseline_sane`, `a17_tag`, `split:gto:random`,
  `split:gto:random_2`, `split:gto:pressure_filler`.
- 500 chips, blinds 1/2, increase every 50 hands, hand cap 10,000.
- Seed 2042, two workers, rotate seats; legacy engine
  `THAI_ENGINE_IMPL=legacy`.

A historical Codespaces control was 23/90 for A17 TAG (25.6%).
No Railway parity test has been run yet. To compare exact runs, ensure the
same seed, code commit, bot order, Python version and other inputs.
The 90-tournament sample is subject to high statistical uncertainty.

## Security and reliability

The public domain serves only the static HTML and a minimal health endpoint
without authentication; all experiment APIs need the secret in the header.
Do not publish the key in logs, screenshots, GitHub or client defaults.
Treat this as a personal/internal tool, not a public multiuser platform.
A service redeploy interrupts active experiments. `/data` persists completed
output only when Railway Volume is attached; long runs consume CPU and memory.
Check Railway usage and billing before lengthy workloads.

```bash
  --chips 500 --sb 1 --bb 2 --blind-increase-every 50 \
  --max-hands 10000 --seat-mode rotate --out output/railway_smoke
```
